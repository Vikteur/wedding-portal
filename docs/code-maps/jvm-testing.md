# Code map: JVM testing

- **Style.** Given-When-Then in the body, one behaviour per test, JUnit 5 and AssertJ (A §13.1, line 876).
- **Method names.** A behaviour sentence in snake case, e.g. `rejects_a_wedding_without_a_date` (A §13.1, line 885; recommendation that settles 18 C-04, line 531). Not `given_when_then`.
- **Two sets, one source tree** (A §13.2, line 888): every class under `src/test/java` whose name does not end in `IT` is the fast set, run by `test`. A class ending in `IT` is the slow set, run by `integrationTest`. No `src/integrationTest` source set.
- **Gradle tasks in this repository** (root `build.gradle.kts`): `test`, `integrationTest`, `startupTest` (tag `quarkus-unit-test`, QuarkusUnitTest in its own JVM), `resourceTest` (tag `resource-test`, datasource-less profile); `check` depends on all of them.
- **Quarkus-booting tests** live only in `application/src/test` (only `application` applies the Quarkus plugin); gateway tests that do not boot Quarkus are ITs in `rekord-gateway`, which alone sets `failOnNoDiscoveredTests = false` (`docs/memory.md`, TASK-4.4).
- **Libraries**: JUnit 5, AssertJ 3.27.7 and WireMock 3 (`wiremock-standalone`) are in `gradle/libs.versions.toml`.
- A unit test that needs Quarkus to pass is in the wrong layer (A §13.2, FW-C-75).
- **One test per Flyway migration.** Every `V<n>__*.sql` in `db/migration` (a dotted version such as `V1.1__x.sql` too: it maps to `V1_1MigrationIT`) has a `V<version>MigrationIT` in `app.rekord.application.persistence.migration` that extends `MigrationSchemaCheck` and declares the schema shape that `SchemaSnapshot` reads from `information_schema` (the base tables of `public` with their columns, types and nullability, their PRIMARY KEY, UNIQUE, FOREIGN KEY and CHECK constraints, and the names of other schemas, and the indexes that back no PRIMARY KEY, UNIQUE or EXCLUSION constraint of their own table, with their `pg_get_indexdef` text) that the history up to that version leaves on an empty PostgreSQL 17 alpine container started for the test. `SchemaSnapshot` does not see column defaults, identity and sequences, views, functions, triggers, extensions, enum labels, collation, exclusion constraints, foreign key on-update, match and deferrability, or the content of other schemas: a migration that depends on one of these needs a test of its own. The fast `MigrationCoverageTest` fails `build` when a V file has no such class (or the class is abstract, `@Disabled`, carries a JUnit condition, overrides the inherited check, or names another version), when a `V*MigrationIT` has no V file, when an entry of the folder is not a top-level versioned migration (a subfolder is refused, since Quarkus and Flyway walk into it and a V file there would run without a test class), or when `strayMigrationFolders` finds a `src/*/resources/db/migration` folder, or a `src/*/java/db/migration` folder (Java-based migrations), outside `application/src/main/resources` (every module's resources reach `classpath:db/migration`). `MigrationSchemaCheckIT` shows the inherited check fail on the fixtures. The snapshot types a column with its length, numeric precision and scale, and a non-default time precision, and refuses a CHECK or FOREIGN KEY name used on two tables (information_schema keys their definitions by name only): give each a table-specific constraint name.
- **Test-only Flyway fixtures** live in `application/src/test/resources/migration-fixtures`, never in a `db/migration` folder of the test resources (it would merge into `classpath:db/migration`).
- **Test beans of a library module** reach `@QuarkusTest` in `application` through a `tests`-classifier jar with its own Jandex index, offered as the configuration `testArtifacts` of `rekord-adapter` and `rekord-usecase` (A §13.3); the row-level rollback proof `RowRollbackIT` uses it.
