# Code map: JVM testing

- **Style.** Given-When-Then in the body, one behaviour per test, JUnit 5 and AssertJ (A §13.1, line 876).
- **Method names.** A behaviour sentence in snake case, e.g. `rejects_a_wedding_without_a_date` (A §13.1, line 885; recommendation that settles 18 C-04, line 531). Not `given_when_then`.
- **Two sets, one source tree** (A §13.2, line 888): every class under `src/test/java` whose name does not end in `IT` is the fast set, run by `test`. A class ending in `IT` is the slow set, run by `integrationTest`. No `src/integrationTest` source set.
- **Gradle tasks in this repository** (root `build.gradle.kts`): `test`, `integrationTest`, `startupTest` (tag `quarkus-unit-test`, QuarkusUnitTest in its own JVM), `resourceTest` (tag `resource-test`, datasource-less profile); `check` depends on all of them.
- **Quarkus-booting tests** live only in `application/src/test` (only `application` applies the Quarkus plugin); gateway tests that do not boot Quarkus are ITs in `rekord-gateway`, which alone sets `failOnNoDiscoveredTests = false` (`docs/memory.md`, TASK-4.4).
- **Libraries**: JUnit 5, AssertJ 3.27.7 and WireMock 3 (`wiremock-standalone`) are in `gradle/libs.versions.toml`.
- A unit test that needs Quarkus to pass is in the wrong layer (A §13.2, FW-C-75).
- **One test per Flyway migration.** Every `V<n>__*.sql` in `db/migration` (a dotted version such as `V1.1__x.sql` too: it maps to `V1_1MigrationIT`) has a `V<version>MigrationIT` in `app.rekord.application.persistence.migration` that extends `MigrationSchemaCheck` and declares the schema shape that `SchemaSnapshot` reads from `information_schema` (the base tables of `public` with their columns, types and nullability, their PRIMARY KEY, UNIQUE, FOREIGN KEY and CHECK constraints, the column defaults and identity settings (`column_default` as PostgreSQL renders it, and `identity_generation` with `identity_start`, `identity_increment`, `identity_minimum`, `identity_maximum` and `identity_cycle`, from `information_schema.columns`), and the names of other schemas; from `pg_index`, the indexes that back no PRIMARY KEY, UNIQUE or EXCLUSION constraint of their own table, with their `pg_get_indexdef` text; and, from `pg_enum`, the enum types of `public` with their labels in order) that the history up to that version leaves on an empty PostgreSQL 17 alpine container started for the test. `SchemaSnapshot` does not see the position of an identity sequence (a `restart` is data), generated columns (their `column_default` is empty), sequences, views, functions, triggers, extensions, enum types of other schemas, collation, exclusion constraints, foreign key on-update, match and deferrability, or the content of other schemas: a migration that depends on one of these needs a test of its own (`SchemaMigrationIT` checks that no view, sequence or extension exists). The fast `MigrationCoverageTest` fails `build` when a V file has no such class (or the class is abstract, `@Disabled`, carries a JUnit condition, overrides the inherited check, or names another version), when a `V*MigrationIT` has no V file, when an entry of the folder is not a top-level versioned migration (a subfolder is refused, since Quarkus and Flyway walk into it and a V file there would run without a test class), or when `strayMigrationFolders` finds a `src/*/resources/db/migration` folder, or a `src/*/java/db/migration` folder (Java-based migrations), outside `application/src/main/resources` (every module's resources reach `classpath:db/migration`). `MigrationSchemaCheckIT` shows the inherited check fail on the fixtures. The snapshot types a column with its length, numeric precision and scale, and a non-default time precision, and refuses a CHECK or FOREIGN KEY name used on two tables (information_schema keys their definitions by name only): give each a table-specific constraint name. The columns of a composite PRIMARY KEY or UNIQUE key are listed in the key's order and the columns a FOREIGN KEY references in the foreign key's mapping order, so a swapped mapping differs; a FOREIGN KEY onto a unique index that backs no constraint is refused by name and table (give the target a PRIMARY KEY or UNIQUE constraint). A NOT NULL is no constraint to the snapshot on PostgreSQL 17 and 18: `SchemaSnapshotIT` runs that check on `postgres:17-alpine` and `postgres:18` and `SchemaSnapshotNotNullCommentTest` keeps the comment at the filter naming both; the Dev Services pins and every `V<n>MigrationIT` stay on 17.
- **Test-only Flyway fixtures** live in `application/src/test/resources/migration-fixtures`, never in a `db/migration` folder of the test resources (it would merge into `classpath:db/migration`).
- **Repository tests** extend `AbstractRepositoryTest` (`app.rekord.application.persistence`, architecture-conventions section 8.5) with `@QuarkusTest`: an injected `EntityManager`, `inNewTransaction`, and `refusal(...)`, which reads a refused row by SQLState and constraint name from the `PSQLException` in the cause chain (the pgjdbc setting `logServerErrorDetail=false` keeps the refused values out of the message). Data comes from `IdentityRows`: `example.com` addresses and made-up names only. Every table of `public` except `flyway_schema_history` is truncated after each test. `Refusals` (same package, with `RefusalsTest`) is the one place that catches a refused statement and looks for a value in the exception graph; `AbstractRepositoryTest.refusal(...)`, `RefusedRowMessageIT` and `IdentityRefusalLoggingIT` all use it. `IdentityRefusalLoggingIT` pins, for a duplicate address, a user status, a session subject and a duplicate `token_hash`, that the refusal names its constraint (read from the cause chain) and that no log line or message shows an address, a password hash or a token hash (the token hash also as a 16-character prefix, because PostgreSQL cuts a long field in its detail). `IdentityCheckRefusalIT` holds a table of refused statements per check constraint with a valid control; `IdentityFieldRoundTripIT` reads every column of sessions and users back by name over JDBC and compares organisations and memberships field by field after `em.find`. `SessionTableIT` reads the `timestamptz` columns back on a connection and a JVM zone of `Pacific/Auckland`, since with `jdbc.timezone=UTC` Hibernate alone cannot tell `timestamp` from `timestamptz`.
- **Test beans of a library module** reach `@QuarkusTest` in `application` through a `tests`-classifier jar with its own Jandex index, offered as the configuration `testArtifacts` of `rekord-adapter` and `rekord-usecase` (A §13.3); the row-level rollback proof `RowRollbackIT` uses it.
- **Test task inputs.** Tests read repository files (`ci.yml`, the `Dockerfile`, build scripts, code-map leaves, `docs/memory.md`, `image-check.sh`) through the `wedding.repoRoot` system property, and `:application:test` declares them as inputs of the task, so an edit runs the tests again without `--rerun`. `repoFiles` is the repository tree minus `.git`, `.gradle`, `.kotlin`, `.idea` (these three at any depth, as `.gitignore` ignores them), `*.iml`, the `build/` and `out/` of the root and of each module (anchored, because a test package is named `build`) and `contract/` (the checkout `contract.spec` points into; the files tests read from it come in as `contractFiles`). Untracked files under the root are inputs too, since `fileTree` does not ask git: that fails safe, with extra reruns only. Gradle's default excludes drop `.gitignore` and `.gitattributes` from any `fileTree`, so the two are named on their own; a new tracked file the defaults drop (a nested `.gitignore`, say) must be named there too, or `TestTaskInputsTest` fails. `contractFiles` is the spec that `contract.spec` names and the `smoke/pom.xml` in the checkout's `smoke/` next to its `dist/` (`HubProbeParityTest` finds it the same way); it is derived from the property, never from a path or a tag, and is optional, so `help` and a run without a contract checkout still configure. `TestTaskInputsTest` pins both, and refuses a `repoFiles` declaration it cannot read (an `include`, a `.matching`, a `.filter`, `excludes`, an `exclude { }` closure, a non-literal `exclude(...)` argument, or a pattern that Ant and a glob read differently). `--rerun` is only needed for state outside them: git state outside the tree (the index for `git ls-files` in `GeneratedSourcesUntrackedTest`; `.git/info/attributes` and git config for `git check-attr` in `GitAttributesTest`, which reads the working-tree `.gitattributes`, an input), the generated sources of `rekord-adapter` (`GeneratedContractTest` reads `rekord-adapter/build/generated/openapi`) and the class directories of other modules (`ClassFileVersionTest`, `ProductionClasses`).
- **Start-up tests of a successful start** (`QuarkusUnitTest`, tag `quarkus-unit-test`, run by `startupTest`, for example `FirstAdminBootstrapIT`): Quarkus loads the test class a second time in its own class loader after the start. So helper classes and the `app.rekord.usecase` package go into the application root of the test, the test classes carry `@Singleton @Unremovable`, `MigratedDatabase` shares its container through system properties instead of static fields, and what the first copy of the class must check after the run is kept in a system property. A use case stays `@ApplicationScoped` without an injection annotation (rule A3), so it must be in the application root of such a test for the client proxy to be generated (`docs/memory.md`, TASK-7.3).
- **Test fakes in `rekord-usecase` carry no CDI annotation.** That test jar is Jandex-indexed into the application tests (the `testArtifacts` configuration), so an annotated fake would become a bean there and compete with the real adapter (`docs/memory.md`, TASK-7.3).
