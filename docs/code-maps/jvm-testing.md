# Code map: JVM testing

- **Style.** Given-When-Then in the body, one behaviour per test, JUnit 5 and AssertJ (A §13.1, line 876).
- **Method names.** A behaviour sentence in snake case, e.g. `rejects_a_wedding_without_a_date` (A §13.1, line 885; recommendation that settles 18 C-04, line 531). Not `given_when_then`.
- **Two sets, one source tree** (A §13.2, line 888): every class under `src/test/java` whose name does not end in `IT` is the fast set, run by `test`. A class ending in `IT` is the slow set, run by `integrationTest`. No `src/integrationTest` source set.
- **Gradle tasks in this repository** (root `build.gradle.kts`): `test`, `integrationTest`, `startupTest` (tag `quarkus-unit-test`, QuarkusUnitTest in its own JVM), `resourceTest` (tag `resource-test`, datasource-less profile); `check` depends on all of them.
- **Quarkus-booting tests** live only in `application/src/test` (only `application` applies the Quarkus plugin); gateway tests that do not boot Quarkus are ITs in `rekord-gateway`, which alone sets `failOnNoDiscoveredTests = false` (`docs/memory.md`, TASK-4.4).
- **Libraries**: JUnit 5, AssertJ 3.27.7 and WireMock 3 (`wiremock-standalone`) are in `gradle/libs.versions.toml`.
- A unit test that needs Quarkus to pass is in the wrong layer (A §13.2, FW-C-75).
- **One test per Flyway migration.** Every `V<n>__*.sql` in `db/migration` (a dotted version such as `V1.1__x.sql` too: it maps to `V1_1MigrationIT`) has a `V<version>MigrationIT` in `app.rekord.application.persistence.migration` that extends `MigrationSchemaCheck` and declares the schema shape that `SchemaSnapshot` reads from `information_schema` (the base tables of `public` with their columns, types and nullability, their PRIMARY KEY, UNIQUE, FOREIGN KEY and CHECK constraints, the column defaults and identity settings (`column_default` as PostgreSQL renders it, and `identity_generation`, from `information_schema.columns`), and the names of other schemas; and, from `pg_index`, the indexes that back no PRIMARY KEY, UNIQUE or EXCLUSION constraint of their own table, with their `pg_get_indexdef` text) that the history up to that version leaves on an empty PostgreSQL 17 alpine container started for the test. `SchemaSnapshot` does not see generated columns (their `column_default` is empty), sequences, views, functions, triggers, extensions, enum labels, collation, exclusion constraints, foreign key on-update, match and deferrability, or the content of other schemas: a migration that depends on one of these needs a test of its own (`SchemaMigrationIT` checks that no view, sequence or extension exists). The fast `MigrationCoverageTest` fails `build` when a V file has no such class (or the class is abstract, `@Disabled`, carries a JUnit condition, overrides the inherited check, or names another version), when a `V*MigrationIT` has no V file, when an entry of the folder is not a top-level versioned migration (a subfolder is refused, since Quarkus and Flyway walk into it and a V file there would run without a test class), or when `strayMigrationFolders` finds a `src/*/resources/db/migration` folder, or a `src/*/java/db/migration` folder (Java-based migrations), outside `application/src/main/resources` (every module's resources reach `classpath:db/migration`). `MigrationSchemaCheckIT` shows the inherited check fail on the fixtures. The snapshot types a column with its length, numeric precision and scale, and a non-default time precision, and refuses a CHECK or FOREIGN KEY name used on two tables (information_schema keys their definitions by name only): give each a table-specific constraint name.
- **Test-only Flyway fixtures** live in `application/src/test/resources/migration-fixtures`, never in a `db/migration` folder of the test resources (it would merge into `classpath:db/migration`).
- **Repository tests** extend `AbstractRepositoryTest` (`app.rekord.application.persistence`, architecture-conventions section 8.5) with `@QuarkusTest`: an injected `EntityManager`, `inNewTransaction`, and `refusal(...)`, which reads a refused row by SQLState and constraint name from the `PSQLException` in the cause chain (the pgjdbc setting `logServerErrorDetail=false` keeps the refused values out of the message). Data comes from `IdentityRows`: `example.com` addresses and made-up names only. Every table of `public` except `flyway_schema_history` is truncated after each test. `Refusals` (same package, with `RefusalsTest`) is the one place that catches a refused statement and looks for a value in the exception graph; `AbstractRepositoryTest.refusal(...)`, `RefusedRowMessageIT` and `IdentityRefusalLoggingIT` all use it. `IdentityRefusalLoggingIT` pins, for a duplicate address, a user status, a session subject and a duplicate `token_hash`, that the refusal names its constraint (read from the cause chain) and that no log line or message shows an address, a password hash or a token hash (the token hash also as a 16-character prefix, because PostgreSQL cuts a long field in its detail). `IdentityCheckRefusalIT` holds a table of refused statements per check constraint with a valid control; `IdentityFieldRoundTripIT` reads every column of sessions and users back by name over JDBC and compares organisations and memberships field by field after `em.find`. `SessionTableIT` reads the `timestamptz` columns back on a connection and a JVM zone of `Pacific/Auckland`, since with `jdbc.timezone=UTC` Hibernate alone cannot tell `timestamp` from `timestamptz`.
- **Test beans of a library module** reach `@QuarkusTest` in `application` through a `tests`-classifier jar with its own Jandex index, offered as the configuration `testArtifacts` of `rekord-adapter` and `rekord-usecase` (A §13.3); the row-level rollback proof `RowRollbackIT` uses it.
